# 서울 시연 경로와 촬영 안내


## 시연 내용

- 세종대로 북행 → 사직로 → 삼청로, 약 1.2km.
- 광화문과 국립민속박물관 인근 도로를 지나며 뱃지 2개를 수집한다.
- 72초 동안 재생한다. 입력 신호의 논리 시간은 4배속으로 288초 진행된다.
- GPS나 지도 API 키, 인터넷 없이 실행된다. 화면의 위치는 명시적으로 표시된 **시연 위치**다.
- 지도는 자체 제작한 오프라인 일러스트다. 도로 경로는 아래 OSM/OSRM 좌표를 사용한다. 배경 건물·공원은 개략 표현이며 실시간 지도나 내비게이션이 아니다.

## 경로 출처

- 데이터: © [OpenStreetMap contributors](https://www.openstreetmap.org/copyright), [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/).
- 경로 생성: [OSRM](https://project-osrm.org/), 공개 driving 라우터, 2026-11-15 조회.
- 요청: `https://router.project-osrm.org/route/v1/driving/126.97728,37.572586;126.980272,37.581925?overview=full&geometries=geojson&steps=true&bearings=0,40;0,40`
- 응답 거리: 1,203.2m. WGS84 경로 45점을 `SeoulDemoRoute.kt`에 보존했다.
- 재생 시 누적 거리로 해당 선분을 찾고 그 선분 내부에서만 보간한다. 회전 지점을 건너 직선으로 연결하지 않는다. 앱 실행 중 외부 라우터를 호출하지 않는다.
- 지도와 차량이 동일한 좌표 투영·경로 데이터를 사용한다. 원본 도로 경로는 [seoul-route.geojson](demo/seoul-route.geojson)에 함께 제공한다.
- 공개 데이터 기반의 고정 시연 경로이며 현장 교통 규제 검증이나 실제 운전 안내를 대체하지 않는다.

## 뱃지 판정과 데이터 분리

`DemoSignalSource → VehicleSignal.Location → RoadDex → InMemoryDexStore → DemoViewModel → Compose`

기존 명소 판정 엔진 `RoadDex`에 좌표를 공급한다. 시간에 맞춰 임의로 뱃지를 표시하지 않는다. 광화문 기준점 140m, 국립민속박물관 기준점 145m 이내에 들어오면 각각 한 번 표시한다. 이 조건은 **프로토타입 명소 통과 판정**이며 기능명세의 F-05 지역 방문 판정(1km/180초)과 다르다.

시연 전용 뱃지 ID는 `demo_` 접두사를 사용한다. 수집 정보와 완료 횟수는 ViewModel 메모리에만 보관한다. 다시 탐험하기는 이번 수집 상태를 초기화하며, 앱 프로세스가 종료되면 세션 기록도 사라진다. 실제 GPS·동의·영구 기록 파일을 읽거나 쓰지 않는다. 백그라운드로 나가면 자동 일시정지한다.

디버그 앱 ID는 `com.roadlog.app.demo`, 기존 차량 앱은 `com.roadlog.app`이다. 별도 설치되므로 기존 앱의 데이터가 덮어써지지 않는다. 시연 Activity와 상세 뱃지 연출은 `src/debug`에만 포함된다. 차량용 release의 주행 중 UI 제한은 그대로 유지한다.

## 촬영 순서

1. `로드로그 Demo` 실행. 가로 화면으로 열린다.
2. 화면 녹화를 시작하고 **서울 탐험 시작**을 누른다.
3. 차량이 세종대로를 따라 이동하고 광화문 뱃지 획득 카드가 표시된다.
4. 사직로에서 삼청로로 이동하며 국립민속박물관 뱃지를 수집한다.
5. 72초 후 **탐험 완료**, `2 / 2`를 확인한다.
6. **도감**에서 두 뱃지, **기록**에서 완료한 시연을 보여준다.
7. 다시 촬영하려면 **다시 탐험하기** 또는 기록의 **새 시연 준비**를 누른다.

일시정지 후 **이어서 탐험하기**로 같은 위치에서 재개할 수 있다. 가로 회전 버튼을 누를 필요가 없다. 에뮬레이터 자체의 `System UI isn't responding`은 앱 크래시와 다르며, 우선 Device Manager에서 Cold Boot를 수행한다. 데이터 삭제(Wipe Data)는 필요하지 않다.

## 검증 범위

자동 검증: 서울 좌표 범위, 코스 거리, 모든 도로 회전점 보존, 프레임 간 도약 방지, 뱃지 순서·중복 방지·재시연, 일시정지·종료·재시작. 기기 화면 검증과 빌드 결과는 [검증 기록](demo/VALIDATION.md)에 기록한다.

실제 Pleos 기기의 GPS/차량 신호, SDK 지도 연동, 실차 UX 승인은 이 시연에서 검증하지 않는다.
