## 1. 서비스 개요

### 1.1 서비스 소개

본 서비스는 운전자가 실제로 주행한 도로와 방문한 지역을 실시간으로 기록하고, 방문한 지역의 상징적인 뱃지와 특별한 칭호를 수집하며, 과거에 지나갔던 도로에서 자신의 이전 주행 흔적을 다시 만나는 **차량 기반 실시간 탐험 서비스**이다.

사용자가 새로운 지역을 방문하면 해당 지역을 대표하는 뱃지를 획득하고, 특정 주행 조건을 달성하면 특별한 칭호를 얻는다.

지도에는 방문 지역의 뱃지와 실제 주행 경로가 기록된다. 미방문 지역을 어둡게 처리하거나 방문한 지역을 밝히는 방식은 사용하지 않는다.

또한 과거에 주행했던 도로를 다시 방문하면 고스트 모드를 통해 이전 주행과 현재 주행을 같은 위치를 기준으로 비교할 수 있다.

### 1.2 핵심 가치

**"처음 가는 길에서는 탐험의 즐거움을, 다시 가는 길에서는 과거의 나와 재회하는 즐거움을."**

기존 내비게이션이 목적지까지의 이동을 지원한다면, 본 서비스는 이동 과정 자체에 새로운 가치를 부여한다.

사용자는 일상적인 주행을 통해 방문 지역의 뱃지와 특별한 칭호를 수집하고, 자신만의 주행 기록을 축적한다.

### 1.3 서비스 목표

- 일상적인 운전을 탐험과 수집의 경험으로 전환한다.
- 방문 지역을 상징적인 뱃지로 기록한다.
- 실시간 보상과 기록 축적을 통해 지속적인 이용을 유도한다.
- 과거 주행 기록을 현재 주행과 연결하여 차별화된 차량 경험을 제공한다.

## 2. 문제 정의 및 타깃 사용자

### 2.1 문제 정의

일반적인 운전 경험은 목적지 도착에 집중되어 있다. 운전자는 다양한 지역과 도로를 지나지만, 이러한 경험이 별도의 성취나 수집 기록으로 남는 경우는 제한적이다.

기존 이동 기록 서비스는 운행 종료 후 통계를 확인하는 방식이 많으며, 사용자가 과거 기록을 다시 열어볼 동기가 부족할 수 있다.

본 서비스는 이러한 문제를 **실시간 지역 방문 인식, 수집형 보상, 과거 주행과의 연결**을 통해 해결하고자 한다.

### 2.2 주요 타깃 사용자

**핵심 타깃: 운전 자체를 즐기는 20~40대 운전자**

일상적으로 차량을 이용하거나 드라이브 및 자동차 여행을 즐기며, 방문 기록을 수집하는 경험에 흥미를 느끼는 사용자이다.

**확장 타깃**

- 장거리 드라이브와 국내 여행을 즐기는 운전자
- 다양한 지역을 방문하고 기록하는 것을 좋아하는 사용자
- 매일 같은 길을 이용하지만 주행 과정에 새로운 재미를 원하는 운전자
- 업적 달성 및 수집형 게임 요소를 선호하는 사용자

## 3. 핵심 서비스 기능

본 서비스는 네 가지 핵심 기능으로 구성한다.

### 3.1 실시간 주행 지도 및 지역 방문 기록

**목적:** 실제로 주행한 도로와 방문한 지역을 기록하고, 방문 경험을 지도와 뱃지를 통해 직관적으로 확인할 수 있도록 한다.

**주요 기능**

1. 기본 지도는 일반적인 지도 형태로 제공한다.
2. 사용자의 차량 위치를 실시간으로 수신한다.
3. 차량이 지나간 도로를 주행 경로로 기록한다.
4. 새로운 행정구역에 방문하면 방문 조건을 검증한다.
5. 방문 조건을 만족한 지역의 뱃지를 자동으로 획득한다.
6. 획득한 뱃지를 지도상의 해당 지역에 표시한다.
7. 과거 주행 경로와 방문 지역 기록을 지속적으로 보관한다.

**지도 표현 원칙**

- 방문 여부와 관계없이 일반적인 지도 배경을 유지한다.
- 미방문 지역을 어둡게 처리하지 않는다.
- 방문한 지역의 배경색을 변경하거나 영역 전체를 밝히지 않는다.
- 실제로 지나간 도로는 주행 경로 선으로 표현할 수 있다.
- 획득한 지역 뱃지는 해당 지역의 위치와 연결해 표시한다.
- 뱃지를 선택하면 획득 날짜와 관련 주행 기록을 확인할 수 있다.

**핵심 차별점**

기존 지도 개방형 탐험 서비스와 달리, 지도의 어두운 영역을 제거하는 방식이 아닌 **지역을 상징하는 뱃지를 수집하여 나만의 방문 지도를 완성하는 방식**을 사용한다.

지도는 탐험 결과를 확인하는 공간이며, 지역 방문의 성취는 뱃지를 통해 표현한다.

### 3.2 뱃지 및 칭호 시스템

**목적:** 지역 방문과 특별한 주행 경험을 영구적인 수집형 보상으로 전환한다.

#### A. 지역 뱃지

대한민국 시·군·구 단위를 기본 수집 대상으로 설정한다.

사용자가 특정 지역에서 유효한 주행 조건을 만족하면 해당 지역의 뱃지를 획득한다.

**뱃지 디자인 원칙**

지역의 특징을 표현할 수 있는 상징물을 활용한다.

선정 우선순위는 다음과 같다.

1. 대표적인 랜드마크
2. 지역의 자연경관
3. 특산물 및 지역 문화
4. 지역명을 활용한 공통 엠블럼

모든 뱃지는 통일된 외형을 사용하고, 내부에 해당 지역을 대표하는 일러스트를 배치한다.

미획득 뱃지는 뱃지 도감에서 어둡게 표시하고, 획득 시 원래 디자인을 공개한다. 이러한 효과는 뱃지 도감에만 적용하며 지도 영역에는 적용하지 않는다.

#### B. 대학 뱃지

대학교를 별도의 방문 수집 대상으로 설정한다.

대학교의 대표 건축물이나 캠퍼스를 상징하는 요소를 활용한 뱃지를 제공한다.

차량이 합법적으로 접근할 수 있는 대학 주변 도로와 지정된 방문 구역을 기준으로 획득 여부를 판정한다.

공식 교표 및 마스코트는 사용하지 않으며, 디자인 권리를 확인한 자체 일러스트를 우선 사용한다.

#### C. 칭호

칭호는 일반적인 지역 방문을 넘어 특별한 주행 조건을 만족했을 때 지급한다.

| 칭호 예시 | 획득 조건 |
| --- | --- |
| 동해에서 서해로 | 동일 날짜에 동해안과 서해안 지정 지점 방문 |
| 전국 탐험가 | 일정 수 이상의 서로 다른 지역 방문 |
| 새로운 길의 발견자 | 신규 도로 탐험 거리 목표 달성 |
| 다시 찾은 길 | 과거 주행했던 특정 구간 재방문 |

칭호는 달성 조건, 획득 날짜, 관련 주행 기록을 함께 저장한다.

장거리 업적은 속도 경쟁이나 무리한 운전을 유도하지 않도록 설계하며, 실제 운영 전 안전성을 검토한다.

**보상 체계**

- 뱃지: 지역 또는 대학 방문을 나타내는 수집품
- 칭호: 특별한 주행 성취를 나타내는 보상

별도의 경험치, 레벨, 게임 재화 시스템은 도입하지 않는다.

### 3.3 주행 아카이브

**목적:** 사용자의 탐험 경험을 기록으로 보존하고, 획득한 보상과 실제 방문 이력을 연결한다.

주행 시 자동으로 기록되는 정보는 다음과 같다.

| 기록 항목 | 내용 |
| --- | --- |
| 주행 일시 | 시작 및 종료 날짜와 시간 |
| 주행 경로 | 실제 이동한 GPS 경로 |
| 주행 거리 | 기록된 이동 거리 |
| 방문 지역 | 주행 중 방문한 행정구역 |
| 획득 보상 | 해당 주행에서 획득한 뱃지와 칭호 |
| 주행 특성 | 사용 가능한 차량 데이터를 활용한 주행 통계 |

사용자는 뱃지를 선택하여 해당 지역의 최초 방문 일자와 관련 주행 기록을 확인할 수 있다.

주행 아카이브는 서비스의 보조 기능으로 제공하며, 사용자가 과거 기록을 직접 확인하지 않아도 핵심 탐험 경험이 성립하도록 한다.

### 3.4 실시간 고스트 모드

**목적:** 운전자가 과거에 지나갔던 도로를 다시 달릴 때, 이전의 자신과 현재의 자신을 실시간으로 연결하여 재방문의 즐거움을 제공한다.

**핵심 개념**

고스트 모드는 과거 주행과 경쟁하는 기능이 아니다.

서로 다른 시점에 같은 도로를 지나갔던 사용자의 기록을 연결하여, 과거의 경험과 현재의 경험을 비교하는 기능이다.

#### A. 고스트 모드 활성화

1. 현재 차량 위치를 수신한다.
2. 저장된 과거 주행 경로와 비교한다.
3. 동일한 도로의 동일 진행 방향에 해당하는 구간을 탐색한다.
4. 일정 길이 이상 경로가 일치하면 고스트 비교가 가능한 구간으로 판정한다.
5. 해당 구간에서 과거 주행 데이터를 현재 위치와 동기화한다.

출발지와 목적지가 다르더라도 실제로 동일한 도로를 지나간 경우 비교할 수 있도록 설계한다.

#### B. 실시간 비교 요소

| 비교 항목 | 제공 정보 |
| --- | --- |
| 과거 방문 정보 | 해당 도로를 처음 지나간 날짜 |
| 경로 비교 | 과거 주행과 현재 주행의 일치 구간 |
| 새로운 발견 | 과거에 방문하지 않았던 도로의 발견 여부 |
| 주행 스타일 | 동일 구간에서 측정한 주행 특성의 변화 |

주행 스타일 비교에는 차량 SDK에서 실제로 제공되는 데이터만 활용한다.

과거의 속도를 추격하거나 이전 기록보다 빠르게 도착하도록 유도하는 기능은 제공하지 않는다.

#### C. 고스트 표현 방식

현재 차량의 위치와 같은 도로 지점에 대응하는 과거 주행 흔적을 표현한다.

주행 중에는 실시간 비교 데이터를 처리하되, 운전자에게 보여주는 정보는 Pleos의 주행 안전 및 앱 카테고리 정책에서 허용하는 수준으로 제한한다.

정차 상태에서는 과거 경로와 현재 경로를 겹쳐 보여주거나, 동일 구간의 주행 특성을 상세하게 비교할 수 있도록 한다.

**핵심 사용자 경험**

"이 길을 예전에도 지나갔구나."

"그때와 지금은 같은 길을 어떻게 달렸을까?"

고스트 모드를 통해 재방문 자체가 새로운 탐험 경험이 되도록 한다.

## 4. 사용자 경험 설계

### 4.1 기본 이용 흐름

**운전 시작 → 실시간 주행 경로 기록 → 방문 지역 뱃지·칭호 획득 → 과거 주행 구간 재방문 시 고스트 비교 → 주행 기록 저장**

사용자는 탐험을 위해 별도의 목적지를 설정하거나 미션을 선택할 필요가 없다.

일상적인 주행만으로 방문 기록과 업적이 누적된다.

### 4.2 주행 중 사용자 경험

- 차량 위치 기반 주행 정보 자동 수집
- 신규 방문 지역 실시간 판정
- 뱃지와 칭호의 획득 조건 실시간 판정
- 과거 주행 구간 자동 인식 및 고스트 데이터 비교
- 승인된 경우에만 운전자 주의를 분산시키지 않는 최소한의 상태 정보 제공

뱃지 획득 애니메이션, 고스트 이동 애니메이션, 반복적인 음성 알림 등은 주행 안전 정책에 따라 제한한다.

실시간 데이터 처리와 실시간 화면 노출을 구분하여 설계한다.

### 4.3 정차 중 사용자 경험

- 방문한 지역의 뱃지가 표시된 지도 확인
- 실제 주행 경로 확인
- 획득한 지역·대학 뱃지 및 칭호 확인
- 주행 아카이브 조회
- 고스트 경로와 주행 통계 상세 비교

### 4.4 주요 화면

| 화면 | 핵심 요소 |
| --- | --- |
| 탐험 지도 | 주행 경로, 방문 지역 뱃지, 현재 위치 |
| 뱃지 도감 | 지역·대학 뱃지, 특별 칭호 |
| 주행 기록 | 과거 경로, 방문 기록, 고스트 비교 |

전체 화면 구성은 세 개의 주요 화면으로 제한한다.

## 5. 기술 구현 계획

### 5.1 개발 환경

- 플랫폼: Pleos Connect
- 개발 언어: Kotlin
- 주요 기술: Android SDK, Pleos Connect SDK
- 데이터 저장: Room 기반 로컬 데이터베이스
- 지도 처리: 지도 렌더링 및 위치 경로 처리 기능
- 테스트 환경: Pleos Connect Emulator

### 5.2 Pleos SDK 활용

### 5.4 주요 처리 방식

**주행 경로 기록**

수신한 GPS 위치 데이터를 검증하고, 실제 이동한 경로를 지도상의 선으로 표시한다.

방문 지역의 지도 영역을 밝히거나 어둡게 처리하는 기능은 구현하지 않는다.

**뱃지 판정**

GPS 좌표와 행정구역 또는 대학 방문 구역 데이터를 비교한다.

방문 조건이 충족되면 해당 뱃지를 지급하고, 지도상의 지역 위치와 연결한다.

**고스트 비교**

과거 GPS 경로와 현재 주행 경로에서 동일 도로 및 진행 방향에 해당하는 구간을 찾는다.

두 경로가 일치하는 지점을 기준으로 과거 주행 정보를 현재 주행과 대응시킨다.

**데이터 저장**

주행 기록은 우선 로컬에 저장하고, 인터넷 연결이 불안정한 상황에서도 기록이 유지되도록 설계한다.

## 6. 경쟁 서비스 대비 차별성

기존 위치 기반 탐험 서비스인 Fog of World 등은 사용자가 지나간 지역을 지도에서 개방하는 경험을 제공한다.

본 서비스는 지도 영역 개방을 핵심 경험으로 사용하지 않고, **지역을 상징하는 뱃지 수집과 실시간 고스트 경험**을 중심으로 차별화한다.

| 구분 | 기존 지도 개방형 서비스의 대표적 기능 | 본 서비스 |
| --- | --- | --- |
| 지도 표현 | 미방문 지역을 어둡게 표시 | 일반 지도 배경 유지 |
| 방문 기록 | 지역 개방으로 표현 | 지역별 상징 뱃지 |
| 수집 보상 | 탐험률 및 업적 | 지역·대학 뱃지, 특별 칭호 |
| 주행 경로 | 탐험 경로 저장 | 실제 주행 경로 누적 기록 |
| 고스트 모드 | 서비스별 지원 여부 상이 | 실시간 위치 기반 과거 주행 비교 |
| 플랫폼 | 주로 모바일 중심 | Pleos 차량 환경 중심 |

**핵심 차별점은 방문 지역 뱃지 수집과 실시간 고스트 모드의 결합이다.**

처음 방문하는 지역에서는 새로운 뱃지를 수집하고, 이미 방문한 도로에서는 과거의 자신과 재회하는 경험을 제공한다.

## 7. 사업성 및 지속 이용 전략

### 7.1 지속 이용 동기

사용자는 일상적인 운전만으로 방문 기록과 주행 기록을 쌓을 수 있으므로, 서비스를 이용하기 위해 별도의 활동을 수행할 필요가 없다.

주요 지속 이용 요인은 다음과 같다.

- 새로운 지역의 뱃지를 획득하는 성취감
- 특별한 칭호를 수집하는 즐거움
- 과거에 지나갔던 도로를 재방문할 때 발생하는 고스트 경험
- 시간이 지날수록 풍부해지는 개인 주행 및 방문 기록

### 7.2 사업 확장 가능성

초기에는 개인 사용자를 중심으로 서비스를 운영한다.

이후 지자체 및 대학과의 협업을 통한 공식 방문 뱃지 제공과 지역 홍보 콘텐츠 연계를 검토할 수 있다.

초기 공모전 버전에는 제휴 서비스나 별도의 상업 기능을 포함하지 않는다.

### 7.3 주요 성과 지표

| 지표 | 측정 목적 |
| --- | --- |
| MAU | 월간 활성 사용자 규모 |
| 주간 탐험 이용률 | 실제 방문·탐험 경험 발생 비율 |
| 30일 재이용률 | 장기 이용 및 유지 여부 |
| 사용자별 획득 뱃지 수 | 수집 참여도 |
| 고스트 모드 경험률 | 차별화 기능의 실제 이용 정도 |

구체적인 목표 수치는 프로토타입 테스트와 초기 사용 데이터를 기반으로 산정한다.

## 10. 기대 효과

### 사용자 관점

평범한 일상 운전에서 탐험과 수집의 즐거움을 경험할 수 있다.

사용자는 방문한 지역의 상징적인 뱃지를 수집하고, 시간이 지날수록 자신의 탐험 경험을 시각적으로 축적한다.

과거에 방문했던 도로에서는 이전의 자신과 연결되는 새로운 경험을 얻는다.

### 플랫폼 관점

차량 위치와 주행 데이터를 기반으로 모바일 환경과 차별화된 인카 서비스를 제안한다.

단순한 정보 제공을 넘어, 운전자가 차량을 이용하는 과정 자체에 새로운 사용자 경험을 부여한다.

### 서비스 관점

방문 지역의 뱃지 수집과 특별 칭호를 통해 지속적인 이용 동기를 형성하고, 고스트 모드로 반복적인 주행에도 새로운 가치를 제공한다.

## 11. 결론

본 서비스는 차량의 이동 과정에 탐험, 수집, 재방문이라는 경험을 결합한 실시간 차량용 앱이다.

사용자는 새로운 지역을 방문할 때 해당 지역의 특징을 담은 뱃지를 획득하고, 특별한 주행 조건을 달성하면 칭호를 얻는다.

지도에는 실제 주행한 경로와 획득한 지역 뱃지가 누적되며, 사용자는 이를 통해 자신만의 방문 지도를 완성한다.

과거에 지나갔던 도로를 다시 방문하면 고스트 모드를 통해 이전의 자신과 현재의 자신을 연결한다.

이를 통해 단순한 이동 기록 서비스를 넘어, **운전하는 모든 순간이 하나의 탐험이자 축적되는 경험이 되는 서비스**를 지향한다.

**서비스 핵심 문구**

> 처음 가는 길은 새로운 발견이 되고, 다시 가는 길은 과거의 나와의 만남이 된다.
