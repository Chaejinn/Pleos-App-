# 기능별 구현 결정

기준: 기능명세서 2026-11-11 · 적용 버전: 2

이 문서는 원문 수치를 유지하면서 상태·중복·경계 처리 규칙을 결정한다. 외부 SDK가 실제 제공하는 API나 Pleos 허용 정책을 추측하지 않는다.

## 1. 원문의 모호한 부분에 대한 결정

## 3. 동의·주행·UI 상태

동의와 위치 권한은 모든 기록의 선행 조건이다. 철회 시 구독·처리를 중단하고 활성 Trip을 현재까지의 승인 데이터로 종료한다. 기존 기록은 별도 삭제 요청 전까지 보존한다. 권한 실패를 가상 좌표로 대체하지 않는다.

### Trip 상태

- IDLE에서 유효한 D/R 진입을 확인하면 시작한다. 앱 시작 시 처음 관측한 D/R도 시작 조건으로 처리한다.
- RECORDING 중 D↔R, D→N→D는 같은 Trip이다. P에 진입하면 즉시 종료한다.
- 주차 브레이크 체결은 PAUSED이며 Trip을 닫지 않는다. 해제 후 P가 아니고 주행이 확인되면 재개한다.
- 기어를 지원하지 않을 때만 속도 시작 대체 조건을 쓴다. 연속 30초 동안 승인된 위치는 메모리에 보류하고 시작 확정 시 해당 구간부터 포함한다. 동의 전 데이터는 보류하지 않는다.
- P 여부와 별개로 속도 0이 5분 이어지면 F-02대로 종료한다. 시작 조건의 연속성이 다시 성립해야 다음 Trip이 생긴다.
- 시작·종료·정차 타이머는 위치 콜백이 없어도 Tick으로 평가하되 오래된 신호를 최신 증거로 쓰지 않는다.
- 프로세스 재시작 후 활성 Trip이 있어도 중단 구간을 직선으로 잇지 않는다. 새 관측으로 재개하고 별도 path segment를 시작한다.

### UI 접근

P 또는 주차 브레이크 체결과 속도 정보가 모순되지 않을 때 PARKED다. 속도 > 0, 신호 모순, 지원 신호의 일시 장애는 RESTRICTED/UNKNOWN으로 취급한다. UNKNOWN은 접근 허용으로 해석하지 않는다.

차량 상태 어댑터는 가능한 신호를 1초 수준으로 갱신하고, 마지막 관측 후 5초가 넘은 값은 UI 허용 근거로 쓰지 않는다. SDK가 변화 때만 알려주면 어댑터가 지원되는 조회 방식으로 신선도를 확인한다. 조회도 불가능하면 UNKNOWN이다. '미지원'과 '지원되지만 오래됨'을 구분한다.

기어·주차 브레이크 신호가 모두 미지원이라고 확인된 경우에만 승인된 속도 0의 연속 10초를 UI 정차 대체 조건으로 쓴다. 미수신 시간은 정지 시간에 더하지 않는다. Pleos가 이 대체 판정을 허용하는지는 채진이 검증하고, 허용되지 않으면 플랫폼 제한이 우선한다.

PARKED에서는 원본 경로 점을 반복 저장하지 않고 정차 지점 한 건만 저장한다. F-05 체류 판정을 위해 위치 확인을 최대 5초 간격으로 유지하는 것으로 정한다. 이는 원문 '정차 시 위치 수신 일시 중지'를 기록 중지와 판정 입력으로 구분한 결정이다. 위치 신뢰도가 끊기면 체류 시간을 더하지 않는다. Trip 종료 후에도 현재 지역 체류 후보는 유지할 수 있고, P 이후 확정된 보상은 직전 Trip이 존재하면 연결하되 삭제된 Trip이면 null 참조로 보관한다.

UI 제한으로 바뀌면 열린 도감·상세·카드를 닫고 S-01 간소 모드로 전환한다. 미확인 카드는 유지한다. 주행 중 숫자 배지·TTS는 원문 수준으로 구현하되 실제 노출은 정책 검증 결과로 제어한다. 검증 전에는 재생 시연에서만 확인하고 배포 허용으로 간주하지 않는다.

## 4. F-01·03 위치·경로 처리

검사 순서는 숫자·좌표 범위 → 정확도 → 시각 순서 → 도약이다. 속도는 null 또는 0 이상이어야 한다. 같은 실행 세션의 입력 순서·경과 시간·도약 검사는 elapsedMs를 사용하고, 동일 시각·역순은 거절하며 마지막 승인 기준점을 유지한다. timeMs는 기록·달력 조건에 사용한다. 벽시계가 바뀌어도 경과 시간 타이머를 다시 계산하지 않는다. 거절된 점을 이후 거리 계산의 기준점으로 바꾸지 않는다.

10초 이상 공백이면 다음 유효점은 새 segment의 첫 점이다. 공백을 건너 도약 검사를 적용하거나 그 거리를 Trip·방문·신규 탐험 거리에 넣지 않는다. 지역 거리·체류 연속성, 고스트 시작 후보도 끊는다.

경로 저장은 승인 스트림과 별개다. 저장 기준의 거리·시간은 직전 **저장점**부터 계산한다. 지역·고스트는 저장되지 않은 1초 승인 위치도 처리한다. 최초·종료·segment 시작점은 간격과 무관하게 보존한다. 지도 단순화는 segment별로 수행해 공백을 가로지르는 선을 만들지 않는다.

100m 격자의 방문 횟수는 `(tripId, gridKey)`당 한 번이다. 신규 거리는 연결 이동 선분을 격자 경계에서 나누고, 이번 Trip 전에 탐험되지 않은 격자 안의 길이를 처음 통과할 때만 누적한다. 같은 Trip의 루프·되돌아감으로 같은 선분 길이를 다시 신규로 더하지 않는다. 이 중복 방지를 위한 Trip 내 처리 선분 정보도 snapshot에 보존한다. 완료 Trip에서 확정하고 F-07 누적에 반영한다.

격자 모델은 한 격자의 미주행 도로까지 이미 탐험한 것으로 근사할 수 있다. 이 제한을 테스트·시연 설명에 기록하고, 정밀 도로 탐험이라고 표현하지 않는다.

F-03 구현(이슈 #3, 2026-11-13)은 `LocationValidator` → `TrackRecorder` → `TrackRecordingStore.commit` 순서다.
`RecordTrackUseCase`는 commit된 snapshot을 매 입력 읽고, 저장 성공 후에만 결과를 반환한다.
정상·거절 입력 모두 큐 sequence를 snapshot에 저장한다. 동일/이전 sequence 재전송은 상태를 바꾸지 않고,
실제 저장 뒤 응답 유실이 발생해도 같은 입력을 다시 누적하지 않는다. 저장 오류 후에는 다음 입력을 진행시키지 않는다.

재시작은 새 sessionId로 명시적 resume한다. 미저장 승인 끝점을 이전 segment에 flush하고 이전 단조 시계 기준을 비운다.
200m 미만 종료는 `DISCARDED`로 정리하고 pending 격자도 전역에 반영하지 않는다. 완료·폐기 상태의 최소 cursor는 종료 재시도에 사용한다.
Room 구현·앱 입력 큐 연결과 이미 확정한 보상 참조 해제는 후속 앱 통합 범위이며, 현재 앱의 legacy 저장 동작은 바꾸지 않았다.

격자 신규 거리 중복 방지는 격자별 처리 선분의 공선 겹침 비율로 계산한다. 완전·부분 되돌아감과 다른 샘플 분할을 처리하며,
비공선 GPS 잡음을 같은 도로로 합치는 map matching은 수행하지 않는다. 자세한 API와 저장 원자성 조건은 [계약 7절](CONTRACTS.md#7-f-03-구현-api와-앱-연결-계약)을 따른다.

검증 기록(2026-11-13): 신규 F-03 테스트 24개, 기존 domain 12개, app 14개 총 50개 통과.
`:app:lintDebug` 오류 0·기존 경고 35개, `:app:assembleDebug` 성공.
JaCoCo 0.8.12로 신규 코드의 instruction 94.3%, branch 84.5%, line 99.7%, method 85.8%를 측정했다.
측정에서 `legacy/**`, 기존 `UserSettings`·`SettingsRepository`를 제외했다. 측정용 로컬 Gradle init script만 사용했으며
공유 Gradle 파일에는 변경이 없다. Android 없는 저장 실패·취소·응답 유실·재시작 테스트이며, 실제 Room·SDK 연결 검증은 후속 통합에서 수행한다.

## 5. F-05·06 방문·보상

- 경계 상자 후보 조회 후 Polygon/MultiPolygon 내부 판정한다. 내부 hole은 제외한다.
- 경계선 위 점은 직전 지역이 후보에 있으면 그 지역을 유지한다. 없으면 code 사전순으로 하나를 선택해 중복 방문 누적을 막는다.
- 지역이 바뀌면 새 entrySequence를 만들고 거리·체류를 0부터 시작한다. 이탈 후 재진입은 이전 후보 누적과 합치지 않는다.
- 서로 다른 지역을 잇는 한 선분은 경계로 잘라 각 지역 내부 길이만 반영한다. 끝점이 속한 지역에 전체 이동 거리를 주지 않는다.
- 방문 거리는 연결된 유효 이동만 누적한다. 체류는 두 유효 관측 사이에 지역 연속성이 확인되는 시간만 누적하고 공백·오래된 위치 시간은 제외한다.
- 1km 또는 3분을 처음 충족하면 VisitQualified를 한 번 만든다. 같은 진입에서 매 위치마다 visitCount를 올리지 않는다.
- 최초 획득이면 뱃지 + 방문 + 미확인 큐를 원자 저장한다. 재방문이면 방문 + visitCount만 갱신하고 신규 보상은 만들지 않는다.
- 대학은 REGION과 다른 badgeId를 사용한다. 실제 합법 접근 구역과 자체 일러스트가 없는 대학은 배포 데이터에 넣지 않는다.

## 6. F-12·13 고스트

현재 Trip을 제외한 주변 과거 포인트를 조회하고 같은 과거 Trip의 시간 순서·진행 방향·segment 연속성을 확인한다. 방향 차이는 원형 각도 최솟값이므로 359°와 1°의 차이는 2°다. 방향 미확인은 고스트 후보에 사용하지 않는다.

단일 과거 Trip·연속 구간에서 30m·45° 조건이 500m 이어져야 시작한다. 서로 다른 과거 Trip의 짧은 조각을 합쳐 500m를 만들지 않는다. 여러 후보가 조건을 만족하면 해당 구간 통과 시각이 가장 최근인 후보를 선택하고, 구간이 끝날 때까지 비교 대상을 고정한다. 동일 시각이면 tripId 사전순으로 결정한다.

일치 거리와 불일치 거리를 분리한다. 일치 시 불일치 거리는 0으로 초기화한다. 활성 전 일치가 끊기면 시작 후보 누적을 초기화한다. 활성 후 불일치 200m이면 마지막 일치점에서 구간을 닫는다. 불일치 200m는 matchedDistanceM에 포함하지 않는다. Trip 종료·수신 공백에서도 활성 구간을 마지막 유효 일치점에서 닫는다.

최초 통과일은 같은 매칭 구간에 대응하는 과거 기록들 중 가장 오래된 관측으로 계산한다. 30일 조건은 현재 주행을 반영하기 전 가장 최근 통과를 사용한다. 구간 일부만 30일을 만족하면 전체 5km를 만족한 것으로 계산하지 않는다.

F-13의 newRoadM 범위는 **고스트 종료 뒤부터 다음 고스트 시작 또는 Trip 종료까지**로 정한다. 종료 직후 결과를 만들고, 이후 신규 거리만 같은 결과 ID에 갱신한다. 큐 항목은 결과 ID로 중복 생성하지 않는다. 마지막 결과는 Trip 종료 시 확정한다.

동일 위치와 방향만으로 입체 교차·평행 도로를 완전히 구분할 수 있다는 보장은 없다. 시연 경로에 반대 방향·평행 도로·교차 사례를 넣고 오탐을 기록한다. 추가 도로 데이터 검증 없이 '동일 도로 판정이 완벽함'으로 표시하지 않는다.

## 7. F-07 칭호·F-10 큐

칭호 ID는 `COAST_TO_COAST`, `REGION_EXPLORER`, `NEW_ROAD_DISCOVERER`, `ROAD_REVISITOR`다. 첫 달성만 저장하고 titleId 유니크 제약으로 중복 획득을 막는다. REGION 개수에 대학을 섞지 않는다. Trip 삭제로 이미 받은 칭호나 누적 탐험 성취를 되돌리지 않는다.

보상은 저장 성공 후에만 확정한다. 정차 카드는 occurredAtMs → id 순서로 보여주고, 사용자 확인 때 한 건씩 acknowledge한다. 한꺼번에 큐를 지운 뒤 카드를 띄우지 않는다. 주행으로 전환하면 표시만 중단한다.

TTS는 사용자 ON·주행 상태·플랫폼 허용이 모두 충족될 때만 실행한다. 60초 제한 중 발생한 알림은 뒤늦게 몰아서 읽지 않고 음성만 생략한다. 큐의 시각적 확인 상태는 그대로 둔다. 앱 재시작 시 과거 큐를 다시 음성으로 읽지 않는다. 고스트 결과는 속도·소요 시간 경쟁 문구 없이 과거 방문일 또는 구간 정보만 사용한다.

## 8. F-15 지표

이름이 비슷한 SDK 신호를 임의로 대응하지 않는다. SteeringWheel 각도, 페달·주차 브레이크, 누적 연료 사용량·잔량은 다른 의미다. 채진은 단위·부호·누적/순간값·관측 주기를 확인하고 어댑터에서 계약에 맞게 변환한다.

| 지표 | 집계 기준 |
| --- | --- |
| 급제동 | 유효 속도 차분의 감속도 ≥3.0m/s²인 연속 상태를 한 번 센다. 신호 회복 후 재진입 때 새 이벤트. Brake 페달은 지원 시 보조 근거이며 별도 필수 조건을 만들지 않음 |
| 급조향 | 속도 ≥20km/h이고 각속도 절댓값 ≥180°/s인 연속 상태를 한 번 센다. 부호·각도 단위 확인 필수 |
| 방향지시등 | 핸들 절댓값이 90°를 처음 넘을 때 회전 1건, 30° 미만 복귀 후 다음 회전. 직전 5초 안에 회전 방향과 맞는 LEFT/RIGHT가 있으면 사용 1건. HAZARD 제외 |
| 사용률 | signaledTurnCount / turnCount. 회전 0건 또는 신호 미지원이면 null |
| 평균 효율 | 같은 구간 유효 거리 km / 소비 연료 L 또는 소비 전력 kWh. 소비량 0 이하·리셋·지원 불가면 null. 연료와 전력 효율을 섞지 않음 |
| 주행 거리 | 유효 적산거리 차이는 보조 통계로 보존하고 GPS 거리와 비교. 단위·리셋 오류가 있으면 GPS 기반 핵심 기능 유지 |

1km 구간과 Trip 종료 시 잔여 구간을 집계한다. 센서 표본 간격이 5초를 넘거나 순서가 역전되면 미관측 구간을 건너 미분하지 않는다. 결측 지표를 0건으로 채우지 않는다. 회전 판정·신호 선행 5초 검사는 원본 센서 시각을 사용한다.

고스트 비교는 같은 공간 구간을 사용한다. 서로 다른 1km 구간의 전체 통계를 단순히 빼지 않는다. 동일 범위를 재집계할 자료가 없는 부분 중첩은 해당 metricsDiff를 null로 둔다. 동일 범위·같은 단위·충분한 관측을 충족한 지표만 비교한다.
