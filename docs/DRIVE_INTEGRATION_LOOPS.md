# 주행 기능 Android 통합 검증

2026-11-15 · 로컬 작업 · main 기준 92779e2

## 원격 반영 범위

origin fetch 후 main에는 추가 변경이 없음을 확인했다. 사용자 지시에 따라 merge_jhmin의 데이터·웹 지도·저장 변경은 통합하지 않았다. main에 병합된 F-02·05·07·12·13만 현재 앱 코드에 연결한다. 이번 작업에서 커밋·push·병합 커밋은 만들지 않는다.

## 반복 검증 단계

1. 칭호: F-07 TitleStore, 지역 30개 칭호, GPS 신규 도로 누적 칭호, 중복 보상 방지, 주행 삭제 후 칭호 유지.
2. 고스트: GhostStore·GhostComparisonStore, 완료 GPS 원본 이력, F-03/F-12/F-13 순차 전달, 정차 결과 조회, 과거 주행 삭제 시 nullable 참조 해제.
3. 저장 실패: 모든 저장 어댑터가 Room coroutine transaction을 공유한다. GPS 시작·한 입력·종료의 F-03/F-05/F-07/F-12/F-13 저장을 하나의 외부 트랜잭션으로 묶었다. 강제 오류 후 모든 revision rollback과 동일 입력 재시도를 검증한다.
4. 출처 분리: 합성 재생의 roads와 GPS의 gps:roads를 분리한다. 신규 도로 칭호 진행은 GPS 영구 도로 행의 firstExploredDistanceM 합계이며 주행 삭제 후에도 보존한다. 같은 길 재주행은 누적을 늘리지 않는다.
5. 중단 복구: 저장된 GPS 주행·고스트 checkpoint를 새 세션으로 복구하면서 공백을 끊고 비교 결과를 종료한다. 이전 구현에서 고스트 checkpoint가 없는 기록에는 결과를 추정해 만들지 않는다.
6. F-02: DriveLifecycleSession이 동의·권한·차량·승인 위치·타이머 입력을 받아 상태기계를 실행한다. 시작 후보 위치를 원래 순서로 기록하고, 일시중지·재개에서 경로를 끊으며 종료 때 기록·보상·상태를 함께 저장한다. 같은 입력 sequence는 재적용하지 않는다.

## 실행 범위

- 일반 Android GPS 진단 모드는 기존 수동 시작·종료를 유지한다. 이 입력을 F-03·방문·고스트·칭호 저장에 연결했다. 실제 GPS 지표가 없는 필드를 만들어 채우지 않는다.
- 새 debug 전용 자동 시작·종료 판정 재생은 합성 D → 승인 위치 31개 → P를 같은 상태기계와 저장 계층으로 처리한다. 1초 관측 간격을 200ms 대기로 재생한다. 실제 차량 신호·위치 검증이 아니다.
- 합성 재생은 실제 지역 배지·GPS 신규 도로 칭호·실제 GPS 고스트 이력을 변경하지 않는다. 명시적 테스트 fixture에서만 합성 영역·과거 기록을 주입한다.
- 지역 경계 데이터·카카오 키는 현재 없는 상태다. 실제 지도 표시와 실지역 방문 시연은 아직 검증하지 않았다.
- release 차량 경로도 새 상태기계에 연결했다. Pleos gear와 CarProperty 속도 콜백은 표준 GPS 위치와 독립적으로 처리한다. SDK fused confidence를 accuracyM으로 변환하지 않는다. 표준 GPS_PROVIDER와 정확한 위치 권한이 없으면 오류로 중단한다. 기어 UNKNOWN은 결측, 번호 기어는 OTHER이며 D로 추정하지 않는다.
- 새 차량 경로의 관측 시각은 차량 콜백 수신 시각(단조 시계)이며 차량 센서 원본 시각 검증과 동일하지 않다. 주차브레이크는 AAOS PARKING_BRAKE_ON의 사용 가능한 Boolean을 독립 구독하고 CAR_POWERTRAIN 권한을 선언했다. 페달 브레이크로 대체하지 않는다. SDK 현재 기어 getter를 최대 한 요청씩 주기 조회하고 실제 응답만 새 관측으로 전달한다. 실패를 UNSUPPORTED나 false로 바꾸지 않는다. 실제 Pleos GPS 공급자·차량 콜백·서비스 지속성·UX/GPU 검증은 남아 있다.
- 속성 근거: https://developer.android.com/reference/android/car/VehiclePropertyIds#PARKING_BRAKE_ON
- P/정지 종료는 Trip을 닫지만 관측 대기를 끝내지 않는다. 정차 뒤 승인 위치는 새 TrackPoint를 만들지 않고 지역 방문 엔진에만 전달해 3분 체류를 이어간다. 200m 미만 Trip 폐기 뒤에도 배지는 유지하며 Trip 참조는 null이다. 다음 D/R 입력은 새 Trip을 시작한다.
- 주차브레이크 일시중지는 경로·고스트의 연속성을 끊지만 지역 방문의 연속성을 끊지 않는다. 지역 엔진에는 F-01 승인 위치를 주행·일시중지·정차에 걸쳐 한 번씩 전달한다. 경로의 저장/중단 상태와 별도로 실제 위치 공백·거절 입력만 지역 체류 연속성을 끊는다. 같은 관측 세션의 새 Trip은 후보 진입을 초기화하지 않고 관련 Trip ID만 갱신한다.
- 정차 관측 대기는 주행 중 UI 제한과 별개다. UX 허용 시 도감·기록·보상 확인을 사용할 수 있고, 지도 화면 또는 상시 알림의 기록 대기 종료로 구독을 끝낸다. 데이터 삭제·복구는 관측 대기를 종료한 뒤 허용하며, ViewModel도 오래된 삭제 콜백을 차단한다. 동의 철회·위치 권한 상실 시 관측을 중단한다.
- 일시중지에서도 같은 UX 검사를 따른다. Trip을 끝낸 것처럼 기록 탭으로 자동 전환하지 않으며, 기존 진행 중 경로는 조회만 가능하다. 자동 기록 탭 전환은 실제 Trip 종료 때 실행한다.

## 보존과 제한

- Ghost 결과에 복사한 비교 경로는 원본 삭제 후에도 남는다. 과거 Trip ID와 passage 참조는 null로 바꾸고, 삭제한 현재 Trip의 결과·비교 보상은 제거한다. 보존하는 칭호·배지의 Trip 참조만 해제한다.
- 종료된 detector/comparison checkpoint에는 raw cursor가 있을 수 있어 개별 삭제 때 닫힌 checkpoint들을 정리한다. 다른 진행 중 주행 삭제는 UI·저장 어댑터에서 차단한다.
- 버전 1 GPS 이력은 180일 안의 완료·GPS 출처 원본을 메모리에 읽는다. grid 후보 query는 완전한 원본 edge를 유지하도록 과다 후보를 허용한다. 대용량 인덱스·페이지 조회와 장기 성능 검증은 남아 있다.
- 출처 분리 이전 개발용 기록을 GPS 신규 도로 인덱스로 자동 역산하지 않는다. 실제 배포 데이터 이행은 별도 검증이 필요하다.
- 정차·UX 접근 허용 때 미확인 보상을 FIFO 카드로 표시한다. 확인만 영구 acknowledge하고, 나중에는 이번 화면 세션에서만 미룬다. 삭제·종료·오류·설정 화면 중에는 표시하지 않는다. 앱 재실행 후에는 미확인 상태를 다시 읽는다.
- 보상 음성은 기본 OFF다. ON이어도 최근 3초 안의 D 기어와 최근 5초 이내 브레이크·조향·회전 안내 관측이 모두 있고, 급조향 후 3초·음성 시도 간 60초를 만족할 때만 한 문장 시도한다. 미확인·오래된 안전 입력은 침묵한다. R/P/N/OTHER 기어 수신 때 음성을 종료한다. 일시중지 중에는 음성을 시도하지 않는다.
- 회전 안내 distance의 미터 단위는 현재 사용 중인 navi-data 3.0.4 sources.jar의 TBTInfo KDoc에서 확인했다. 이를 센서 수신·오디오 실제 재생 검증으로 확대 해석하지 않는다.
- 음성 시도 ID를 영구 저장하므로 재실행 때 같은 보상을 반복 발화하지 않는다. 호출 전 안전 상태가 바뀌거나 SDK 재생이 실패하면 음성이 생략될 수 있으며, 보상 acknowledge는 하지 않는다. 음성 오류를 기록 저장 오류로 전파하지 않는다. 실제 SDK 발음·오디오 정책 검증은 남아 있다.
- 도감은 시·도별 3열 그리드, 획득/미획득 상태, 칭호와 배지 상세(조건·최초 획득 시각·방문 횟수)를 표시한다. 카탈로그의 배지 raster asset은 manifest 해시·실제 이미지 크기를 검증하고, 화면에서는 최대 192px thumbnail로 읽는다. 공급한 attribution을 도감에 표시한다. 실제 데이터가 없는 현재 화면에 임의 지역·획득 상태를 채우지 않는다.
- 고스트 비교는 저장된 두 경로를 공통 범위에 맞춰 겹쳐 보는 미리보기를 제공한다. 과거는 연한 굵은 선, 현재는 진한 선이며 경로 구간 사이 공백을 연결하지 않는다. 이 미리보기에는 지도 배경이 없음을 표시한다.
- 차량 지표 비교·지도 마커와 제출 문서 검증은 별도 남은 범위다. 실제 배지 asset 공급·그리드 실데이터 성능·화면 검증도 남아 있다.

## 테스트

AchievementStorageTest, GhostRecordingSessionTest, RecordingAtomicityTest, DriveLifecycleSessionTest에서 실제 Room SQLite와 암호화 payload를 사용한다. 기존 도메인·설정·권한·UX 회귀 테스트도 함께 실행한다. 테스트 통과를 실제 Pleos 차량 검증과 혼동하지 않는다.

- domain 209개 + app debug 71개 = 280개 통과, 실패 0. 별도로 app release 71개 통과. debug/release APK 빌드와 양쪽 lint 통과, 오류 0.
- 일반 API 37 에뮬레이터에서 자동 D/P 판정 재생 후 기록 탭 전환과 합성 출처·334m·1개 경로 구간·시작/종료 시각을 확인했다. 기존 기록 유지.
- 지역 데이터·카카오 키·Pleos 시스템 이미지가 아직 없어 해당 환경의 실제 성공을 검증하지 못했다.

## 로컬 release 서명

- release 서명 키와 설정은 .local/roadlog-release.jks 및 .local/release-signing.properties에만 둔다. 둘 다 Git 제외다. 동일 앱을 계속 업데이트하려면 이 키와 설정을 안전하게 보관해야 한다.
- 네이티브 지도 인증에 필요한 release 공개 키 해시는 .local/kakao-registration.txt에 추가했다. debug 키 해시와 다르므로 카카오 Android 플랫폼 등록에 둘 다 반영해야 한다.
- 서명된 release 후보 빌드는 실제 지도·지역 데이터·Pleos 연동 검증을 통과한 최종 제출본을 뜻하지 않는다. 후보 APK는 .local/artifacts에 보관한다.
- RoadLog-release-candidate.apk는 apksigner의 APK v2 서명 검증을 통과했다. com.roadlog.app, minSdk 28/targetSdk 34, 비디버그 설정을 확인했다. RoadLog-debug.apk와 SHA-256·검증 환경 기록(validation.json)을 같은 폴더에 보관한다. 후보는 로컬 미커밋 소스로 빌드됐으므로 HEAD 해시만으로 소스를 재현할 수는 없다.
- 기존 debug 앱 데이터를 보존했으며, 서명이 다른 release APK로 덮어쓰거나 앱 데이터를 초기화하지 않았다. 실제 release 설치·Pleos 런타임 검증은 남아 있다.
