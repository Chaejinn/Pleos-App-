# 로드로그 서비스 기획서

## 1. 서비스 개요
로드로그는 이동 중 지나간 명소를 수집하고, 실제 이동 경로와 과거의 같은 길을 함께 돌아보는 차량 기반 탐험 서비스다. 목적지 안내나 속도 경쟁을 제공하지 않는다. 이번 통합본은 전국 897개 랜드마크의 좌표를 기반으로 지도, 방문 수집, 도감, 주행 기록을 연결한다.

**서비스 메시지: 처음 가는 길에서는 새로운 발견을, 다시 가는 길에서는 과거의 나와 재회를.**

대상 플랫폼은 Pleos Connect 기반 Android Automotive이며, 개발용 Android 에뮬레이터에서는 표준 GPS 입력과 합성 경로 재생으로 동작을 확인한다. 프로젝트 내부 이름은 RoadLog, 앱 표시 이름은 로드로그, applicationId는 com.roadlog.app이다.

## 2. 원본 기획과 이번 구현의 관계
2026-11-11 기능명세와 기획 v1.1의 장기 목표는 시·군·구 방문 배지다. 사용자가 이번에 제공한 자료는 행정구역 경계가 아닌 개별 관광명소 좌표 897건이다. 따라서 현재 구현의 수집 단위를 **랜드마크**로 명확히 정의한다. 명소 30개 수집을 시·군·구 30개 방문으로 간주하지 않는다.

| 구분 | 현재 통합본 | 후속 범위 |
| --- | --- | --- |
| 랜드마크 방문 | 제공 좌표의 반경에 들어오면 수집 | 좌표 현장 정확도와 차량 접근성 보강 |
| 시·군·구 배지 | 기존 도메인 판정 엔진 보존 | 공식 경계 GeoJSON과 Android 저장·화면 연결 |
| 고스트 | 경로 기록과 기존 판정·비교 엔진 연결 | 실제 Pleos 장거리·성능 검증 |
| 칭호 | 신규 도로 100km, 30일 지난 길 5km 재방문 연결 | 지역 30개·동서해 칭호의 원자료 확보 |
| 지도 | Kakao Android SDK 및 Web SDK 연결 코드 | 앱 키·도메인·서명 등록 후 실제 지도 인증 확인 |

## 3. 사용자와 제공 가치
주 사용자는 국내 여행과 드라이브를 즐기거나 일상 이동을 기록하고 싶은 운전자다. 별도 미션이나 재화를 요구하지 않고, 실제 방문과 경로를 개인 기기에 남긴다. 반복되는 길에서도 같은 방향의 과거 주행과 겹치는 구간을 보여주어 재방문의 의미를 만든다.

- 새로운 명소를 찾는 즐거움: 명소·지역·유형 검색과 지도 마커 제공.
- 방문을 남기는 경험: 반경 진입을 기록하고 최초 획득 시점을 보관.
- 다시 찾는 길의 의미: 같은 방향으로 연속 500m 이상 겹치는 과거 경로 비교.
- 주행 후 돌아보기: 경로, 방문 명소, 획득 칭호와 고스트 결과 조회.

## 4. 핵심 이용 흐름
1. 위치 기록 저장에 동의하고 정확한 위치 권한을 허용한다.
2. 정차 중 GPS 탐험을 시작한다. 차량 신호 연결 모드는 별도 제공한다.
3. 유효한 GPS 위치를 기록하고 명소 반경 진입을 판정한다.
4. 기록 중에는 상세 도감과 보상 카드를 표시하지 않는다.
5. 탐험 종료 후 접근이 허용된 정차 상태에서 획득 카드를 확인한다.
6. 도감에서 명소를 검색하고, 주행 기록에서 경로와 고스트 비교를 확인한다.

온라인 지도는 별도 안내 후 사용자가 켠다. 키가 없거나 지도를 불러오지 못해도 위치 기록·수집은 계속 사용할 수 있다. GPS 탐험은 수동 시작·종료 세션이며, 원본 기획의 완전한 차량 자동 주행 감지를 완료했다고 표현하지 않는다.

## 5. 세 개의 주요 화면
| 화면 | 주요 내용 | 접근 기준 |
| --- | --- | --- |
| 탐험 지도 | 카카오 지도, 과거·현재 경로, 명소 마커, 검색, 탐험 시작 | 상세 조작은 정차 시 |
| 랜드마크 도감 | 수집 개수, 검색·필터·페이지 이동, 명소 설명, 방문 시점, 칭호 | 주행 중 진입 제한 |
| 탐험 기록 | 최신순 주행, 거리·시각·입력 종류, 획득 명소, 고스트 결과, 삭제 | 주행 중 진입 제한 |

미방문 지역을 암전하거나 배경 전체의 색을 바꾸지 않는다. 미수집 명소 카드는 회색, 수집한 명소 카드는 초록 계열로 구분한다. 지도 마커는 수집 여부를 구분하되, 미수집 명소도 찾을 수 있게 표시한다. Web 지도는 전국 확대 수준에서 마커를 묶어 표시한다.

## 6. 데이터와 보상 설계
897개 레코드의 ID·이름·좌표·반경·설명을 보존하여 landmarks.json에 연결했다. 유형은 명소 396개, 관광 182개, 자연 165개, 역사 143개, 다리 8개, 터널 3개다. 제공 반경은 150~500m다.

지역 필드는 원문을 보존한다. ‘전남광주’처럼 합쳐진 표기가 포함되어 있어 공식 행정구역 코드나 정확한 시·도 통계로 사용하지 않는다. 원본 배포 URL·이용조건은 파일에 없으므로 카탈로그 manifest에 미확인 상태를 기록했다. 배포 전 원출처를 확정해야 한다.

하나의 유효한 위치가 여러 명소 반경 안에 있으면 해당 명소를 모두 수집한다. 같은 입력 종류에서 같은 명소는 최초 한 번만 획득한다. 합성 경로 시연의 배지·도로 이력·칭호는 실제 GPS 탐험과 분리한다.

명소 방문은 독립적인 방문 기록으로 보관한다. 200m 미만 주행이 폐기되거나 주행을 삭제해도 이미 받은 명소 배지는 유지하되, 삭제된 주행에 대한 참조는 제거한다. 전체 삭제는 보상을 포함한 저장 기록을 제거한다.

## 7. 기술 구성과 정보 처리
- 앱: Kotlin, Jetpack Compose, Android API 28 이상, compile/target SDK 34.
- 지도: Kakao Maps Android SDK 2.15.2. x86 개발 환경에서는 JavaScript 키를 이용한 WebView 지도를 사용할 수 있다.
- 위치: Android GPS의 시각·정확도·방향·속도를 있는 그대로 사용한다. Pleos 위치의 정확도 의미를 임의 변환하지 않는다.
- 저장: Room의 암호화 레코드 저장소와 Android Keystore 기반 AES-GCM 암호화.
- 판정: 기존 :domain의 위치 검증·경로 기록·고스트·칭호 엔진을 재사용한다.
- 환경설정: Git 제외 .env에 플랫폼 키를 입력한다. .env.example은 빈 설정 예제다.

앱 자체의 주행 경로 업로드 서버는 없다. 다만 온라인 지도 사용 시 카카오의 인증·지도 요청이 발생한다. 이를 ‘외부 통신이 전혀 없는 앱’으로 표현하지 않는다. 앱에 포함되는 플랫폼 키는 APK에서 복구할 수 있으므로 카카오 콘솔의 패키지·서명·도메인 제한을 함께 설정한다.

## 8. 안전과 운영 원칙
운전 중 보상 카드·목록·검색 입력을 제공하지 않는다. AAOS UX 제한 신호를 사용할 수 없으면 상세 화면을 제한하는 기존 정책을 유지한다. 지도의 상세 조작을 위해 주행 중 기기를 조작하도록 유도하지 않는다.

명소 안으로 차량을 진입시키거나 목적지 경로를 안내하는 기능은 아니다. 도로·출입 규정을 우선하며 주행 후 수집 결과를 확인한다. 속도·도착 순위·추격·소요 시간 경쟁은 제공하지 않는다.

## 9. 현재 결과와 후속 작업
현재 소스는 merge_jhmin에 feature/app-integration을 통합한 상태를 기준으로 한다. 사용자 요청에 따라 추가 범위 확장을 멈추고, 현재 변경의 검증과 문서 산출에 집중했다. 상세 검증 결과는 같은 폴더의 VALIDATION.md를 함께 확인한다.

- 실제 카카오 인증·지도 타일·마커 터치·네트워크 복귀 확인.
- Pleos 실기기에서 위치·차량 신호·UX 제한·포그라운드 서비스 검증.
- 시·군·구 경계 데이터, 대학 방문 구역, 동서해 지정 지점 확보.
- 원본 위치 180일 자동 정리, 대규모 기록 성능 및 장애 복구 추가 검증.
- 차량 특성 지표와 고스트 상세 비교 연결. 미측정 값은 임의의 0으로 채우지 않는다.
