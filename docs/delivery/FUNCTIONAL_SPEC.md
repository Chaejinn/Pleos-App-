# 로드로그 기능명세서

## 1. 적용 범위
기준일 2026-11-15. merge_jhmin에 feature/app-integration을 통합하고 사용자 제공 897개 명소를 연결한 구현 기준 명세다. 원본 2026-11-11 명세의 장기 요구사항은 보존하며, 이 문서는 완료된 연결과 남은 범위를 구분한다. 검증의 실제 결과는 VALIDATION.md를 따른다.

## 3. 입력과 경로 기록
정확한 위치 권한 및 별도 기록 저장 동의가 있어야 GPS 탐험을 시작할 수 있다. 입력 종류는 ANDROID_GPS, REPLAY, UNKNOWN으로 구분한다. 원시 위치의 UTC 밀리초와 단조 증가 elapsed 밀리초를 분리한다.

| 항목 | 처리 기준 |
| --- | --- |
| 위치 정확도 | 정확도 값이 없거나 50m 초과이면 거절. 50m는 허용 |
| 유효 좌표 | finite 값, 위도 -90~90, 경도 -180~180 |
| 순서 | 중복·역순 위치 및 처리 sequence 재시도 방어 |
| 위치 도약 | 연속 구간에서 계산 속도 200km/h 초과이면 거절 |
| 수신 공백 | 10초 이상이면 경로 연속성을 끊어 선 연결 방지 |
| 포인트 저장 | 20m 이동 또는 5초 경과 |
| 경로 단순화 | 종료 시 허용 오차 5m |
| 짧은 기록 | 200m 미만은 경로 폐기. 명소 방문 보상은 독립 보존 |
| 신규 도로 | 약 100m 격자와 중복 구간 보정, 입력 종류별 도로 저장 분리 |

GPS 입력은 최대 64개 큐로 직렬 처리한다. 큐 초과·공급자 중단·권한 문제·저장 오류 시 성공으로 가장하지 않고 기록을 중단한다. 중단된 저장 기록은 아카이브에서 저장된 지점 기준으로 복구 종료할 수 있다.

## 4. 랜드마크 카탈로그 계약
파일: app/src/main/assets/catalog/legacy/landmarks.json. 현재 경로를 유지해 기존 로더와의 호환성을 확보한다. 파일명에 legacy가 있지만 이번 도감의 실제 카탈로그다. 데이터 출처·버전·해시는 catalog/manifest.json에 기록한다.

| 필드 | 타입·의미 |
| --- | --- |
| id | 비어 있지 않은 고유 문자열. 수집 이력과 연결하므로 유지 |
| name / region | 명소 이름과 사용자 제공 지역 표기 |
| type | NATURE, LANDMARK, HISTORY, ATTRACTION, BRIDGE, TUNNEL 및 기존 도로 유형 |
| lat / lon | WGS84 위도·경도. 순서 바꾸지 않음 |
| radiusM | 양수 미터. 제공 데이터는 150~500m |
| story | 선택 설명 문자열. 없으면 기본 안내 |

카탈로그 로더는 빈 목록·중복 ID·잘못된 좌표·비정상 반경을 거절한다. 현재 897건의 ID 중복 및 좌표 범위 검증을 통과했다. 좌표 범위 검증은 현장 정확도나 접근 가능성을 보장하지 않는다. ‘전남광주’ 등의 원문 지역 표기는 그대로 유지한다.

## 5. 명소 수집과 보상
F-03이 승인한 위치만 LandmarkCollector에 전달한다. 위도 범위로 후보를 줄이고 두 좌표 간 구면 거리가 명소 radiusM 이하인지 검사한다. 경계값은 포함한다. 여러 명소의 범위가 겹치면 모두 반환한다.

랜드마크 ID와 입력 종류가 같으면 최초 한 번만 저장한다. LandmarkVisit에는 landmarkId, acquiredAtMs, tripId, inputSource, acknowledged를 보관한다. REPLAY 방문은 실제 GPS 방문과 별개다. 도감 기본 표시는 실제 방문이며 시연 기록으로 전환할 수 있다.

경로 업데이트·명소 보상·고스트 계산 결과는 같은 Room 트랜잭션 안에서 반영한다. 저장 실패나 revision 충돌 시 일부만 지급하지 않는다. 정차 상태에서 확인한 보상은 acknowledged=true로 저장해 앱 재시작 후 다시 표시하지 않는다.

주행별 삭제 및 짧은 경로 폐기 시 명소 배지는 유지하고 tripId를 null로 바꾼다. 전체 삭제 시 배지와 칭호를 함께 삭제한다. 이전 데모의 dex.json은 별도 호환 기록이며 새 실제 방문 기록으로 자동 승격하지 않는다.

## 6. 고스트와 칭호
기존 GhostDetector, GhostResultAssembler, TitleEvaluator를 재사용한다. GPS와 REPLAY의 과거 기록을 섞지 않는다. 초기 비교 후보는 저장된 같은 입력 종류의 완료 경로다. 경로 삭제 시 연결된 과거 주행 ID를 해제한다.

- 같은 방향 차이 45도 이내, 반경 30m 이내의 과거 구간과 연속 500m 이상 일치하면 고스트를 시작한다.
- 일치하지 않는 이동이 200m 이어지면 해당 구간을 종료한다.
- 종료된 비교 결과에 일치 거리·최초 통과 시점·이후 신규 거리·현재/과거 경로를 저장한다.
- 기록 종료 시 신규 도로 누적 100km 및 마지막 통과에서 30일 이상 지난 구간 5km 재주행 조건을 평가한다.
- 명소 수집 수를 지역 배지 개수로 전달하지 않는다. REGION_EXPLORER는 지역 경계 연결 전 자동 지급하지 않는다.
- 차량 지표 비교 데이터가 없으면 ‘측정 데이터 없음’을 표시한다. 속도·도착 순위 비교를 만들지 않는다.

현재 과거 경로 캐시는 전체 완료 경로를 대상으로 하므로 기록량이 커질 때 공간 인덱스·메모리·50ms 목표의 기기 성능 검증이 필요하다. 장기 운행 성능 검증을 완료했다고 주장하지 않는다.

## 7. 지도와 환경설정
프로젝트 루트 .env에서 KAKAO_NATIVE_APP_KEY와 KAKAO_JAVASCRIPT_APP_KEY를 읽는다. 시스템 환경변수가 우선하고, 네이티브 키는 기존 .local/kakao.properties 형식도 지원한다. 값의 앞뒤 작은따옴표·큰따옴표를 허용한다. 변경 후 APK를 다시 빌드해야 한다.

| 지도 방식 | 준비 사항 |
| --- | --- |
| Android SDK | 네이티브 앱 키, com.roadlog.app 패키지, 실행 서명의 키 해시 등록 |
| Web SDK | JavaScript 키, https://appassets.androidplatform.net 도메인 등록 |
| 공통 | 카카오 개발자 콘솔에서 해당 앱의 카카오맵 사용 가능 상태 확인 |

키가 없으면 지도 SDK를 시작하지 않고 안내한다. x86 환경에서는 JavaScript 키가 있을 때 Web 지도 경로를 사용한다. Web 문서는 앱에 내장된 HTTPS 원점으로 제공하며 임의 탐색·파일 접근·네이티브 JavaScript 브리지를 허용하지 않는다. 명소 설명은 HTML 삽입이 아닌 텍스트로 표시한다.

온라인 지도는 기본 OFF다. 사용자 안내 후 카카오 요청을 시작한다. 저장된 주행 기록을 앱 자체 서버에 업로드하는 기능은 없다. 지도 표시에 필요한 영역 정보와 네트워크 요청은 외부 제공업체에 전달될 수 있다.

## 8. UI와 상태 제한
탐험 지도·랜드마크 도감·탐험 기록의 세 탭을 사용한다. 검색과 상세 카드는 정차 접근이 가능할 때만 제공한다. 도감은 한 페이지에 12개를 표시해 897개를 한 번에 구성하지 않는다. 터치 대상은 최소 76dp, 기본 본문은 24sp 기준을 유지한다.

기록 중에는 상세 탭과 보상 카드를 숨긴다. AAOS UX 접근이 미확인·제한이면 상세 화면을 제한한다. GPS 탐험 종료 버튼도 차량의 상세 조작 허용 상태에서만 사용할 수 있다. 일반 Android 에뮬레이터는 NON_AUTOMOTIVE 환경으로 표시 정책이 다르므로 실차 안전 검증을 대신하지 않는다.

## 9. 저장과 복구
Room recording_entries에 revision을 포함한 암호화 JSON payload를 저장한다. 기존 DB v1 테이블을 재사용하므로 이번에 파괴적 마이그레이션을 추가하지 않는다. 각 payload는 별도 IV 및 레코드 ID 기반 AAD로 암호화한다.

| 저장 키 | 내용 |
| --- | --- |
| snapshot: / points: / source: | 주행 상태·원본 포인트·입력 종류 |
| roads:ANDROID_GPS / roads:REPLAY | 분리된 신규 도로 이력 |
| landmark-visits | 최초 방문과 미확인 상태 |
| ghost: / comparison: / ghost-results: | 고스트 상태·계산 체크포인트·비교 결과 |
| collected-titles | 칭호·입력 종류·확인 여부 |

삭제된 주행의 배지·칭호는 보존하되 참조를 해제한다. 전체 삭제는 DB와 기존 데모 파일을 제거하며 기록 동의·음성 설정은 보존한다. 지도 캐시 정리는 SDK 수명주기와 별도 처리한다.

## 10. 빌드와 검증 절차
JDK 17과 Android SDK API 34를 준비한 뒤 프로젝트 루트에서 실행한다.

```powershell
./gradlew.bat :domain:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
python scripts/validate_landmarks.py
```

추가 회귀 검증은 897건 전체 로딩, 중복 ID·불량 좌표 거절, 반경 경계, 겹친 명소 동시 수집, 정확도 51m 거절, 재실행 중복 방지, DB 재오픈, 확인 상태 유지, 시연/실제 분리, 짧은 기록 참조 해제, 고스트 2회 경로 재생과 주행 삭제를 다룬다.

수동 확인 순서는 동의 → 온라인 지도 안내 → 명소 검색 → 시연 경로 실행 → 종료 후 획득 카드 → 도감 시연 기록 → 주행 기록 → 두 번째 재생의 고스트 결과다. 실지도 타일은 키뿐 아니라 콘솔 등록이 완료되어야 확인할 수 있다.

## 11. 남은 검증과 인수인계
이 문서는 현재 코드 연결 상태를 설명한다. 최종 자동 검증 결과는 VALIDATION.md에 별도로 남긴다. 원본 시·군·구 배지, 완전한 차량 자동 상태 연결, 신규 보상의 TTS, 180일 원본 정리, 차량 지표 비교, 실차 성능 및 카카오 실지도 인증은 별도 확인 항목이다.

원본 문서는 docs/references에 유지한다. 후속 작업자는 .env를 커밋하지 않고, 기존 팀원의 도메인 임계값을 시연 편의를 위해 바꾸지 않는다. 제공 카탈로그의 원출처·이용조건을 확정한 뒤 배포 문구와 manifest를 갱신한다.
