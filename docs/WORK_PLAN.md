# 담당 작업·통합 계획

일정 기준: 전달받은 기능명세서의 2026-11-15 접수, 12-03~04 PT. 공모전 외부 일정을 새로 검증한 기록은 아니다.

## 1. 바로 시작할 작업

| 담당 | 첫 작업 | 다른 사람을 기다리지 않는 방법 | 첫 전달물 |
| --- | --- | --- | --- |
| 채진 | `:app`, `:domain` 빌드 껍데기와 입력·저장 어댑터 | 도메인 fake와 합성 위치 입력으로 S-01·S-02 구현 | Wrapper 포함 빌드 기반, SDK 검증 기록, 입력 포트 연결 |
| 동현 | 공통 모델·포트 구현, F-03·05 엔진 | in-memory 저장 포트와 합성 폴리곤 사용 | 계약 타입, 검증·기록·방문 단위 테스트 |
| 현민 | 시연 경로·경계·대표 좌표·뱃지·seed | 합성 데이터로 먼저 공통 입력 확정, 실제 지역 데이터는 별도 검증 | 데이터 규격에 맞는 catalog·demo·expected 결과 |

루트 Gradle·모듈 빌드 파일은 채진만 편집하고, 동현은 domain 소스·테스트를 추가한다. 첫 통합 전에 공동 편집이 필요한 경로를 늘리지 않는다.

## 3. 통합 순서와 통과 조건

| 단계 | 통합 흐름 | 통과 조건 |
| --- | --- | --- |
| A | 모델·포트 + fake + 빌드 기반 | domain 테스트 실행, app이 fake 입력 표시 |
| B | 동의 → 입력 → 검증 → Trip → 경로 저장 | 동의 전 0건, 공백 분리, 다시 실행해 경로 확인 |
| C | 지역 데이터 → 방문 → 뱃지·칭호 → 큐 → 도감 | 최초 한 번 획득, 재방문 횟수만 증가, 정차 확인 |
| D | 과거 seed → 고스트 → 비교 결과 → 큐 | 500m 전 비활성, 5km·30일 칭호, 역방향 거절 |
| E | 실제 SDK·지도 + 아카이브·삭제 | 실제·재생 계약 일치, 삭제 후 참조 오류 없음 |
| F | 지원 차량 특성·잔여 칭호·정책 적용 | 지표 결측 독립성, 상세 비교, 배포 조건 검증 |

각 단계는 실제 위치 또는 재생 위치를 같은 입력 포트에 연결한다. 녹화용 가짜 UI 상태를 직접 주입해 판정 완료로 취급하지 않는다.

| 날짜 | 채진 | 동현 | 현민 | 그날 통합 산출물 |

11-11에 실제 SDK 연결이 막히면 재생 입력으로 B~D를 계속 개발하고, SDK 확인 작업은 채진이 병행한다. 영상·문서에 재생 입력 사용을 표시한다. 이를 실제 차량 연동 검증으로 기록하지 않는다.

접수 범위는 명세의 F-01~05, F-07 두 칭호, F-10, F-12, F-13 계산, 탐험 지도·도감 기본 화면이다. F-14의 동의·권한은 이 범위가 동작하기 위한 선행 조건이다. 정차 결과는 P-01과 최소 조회로 확인하며 아카이브 완성은 PT 단계다. 지도 배지 마커 전체 기능은 PT 범위여도 접수 때 완료되면 함께 검증한다.

## 7. 통합 체크리스트

- 동일 데이터에서 세 사람의 실행 결과가 기대 결과와 일치한다.
- 계약 타입·필드·단위를 복제하거나 기능별로 바꾸지 않았다.
- 저장 실패·프로세스 재시작·큐 확인 중 주행 전환을 검증했다.
- Trip 삭제·200m 미만 정리·180일 원본 정리 후 화면 조회가 가능하다.
- 실제 SDK 검증과 재생 입력 테스트 결과를 구분해 기록했다.
- main에서 공통 빌드·테스트를 통과하고 버전·fixture 버전을 함께 기록했다.
