# 개발 착수 문서

기준일: 2026-11-11 · 문서 계약 버전: 1

이 문서 묶음은 채진·동현·현민이 즉시 병렬 개발을 시작하기 위한 적용 기준이다. 별도 합의 회의를 전제로 하지 않는다. 이번 산출물은 개발 규칙과 계약이며, 앱·SDK 연동·알고리즘이 구현되었다는 의미는 아니다.

## 기준 문서의 역할

1. **기능명세서**가 구현할 기능·수치·범위를 결정한다.
2. **이 문서 묶음**이 기능명세서에서 정하지 않은 구조·계약·처리 순서를 결정한다. 기존 요구를 바꾸는 경우에는 변경 내용을 별도로 명시한다.
3. **기획서**는 서비스 목적과 사용자 경험을 이해하는 자료다. 기능명세서와 다르면 기능명세서를 따른다.
4. **작업 순서 원문**은 담당 분리와 병렬 개발의 배경 자료다. 실제 작업 기준은 이 문서 묶음이다.

전달받은 원문은 [references](references/) 아래에 보존한다.

- [기획서 v1.1](references/PLANNING.md)
- [기능명세서 2026-11-11](references/FUNCTIONAL_SPEC.md)

## 이번에 확정한 기준

- 모듈은 `:domain`과 `:app` 두 개로 시작한다. 판정 로직은 Android·Room·Pleos SDK에 의존하지 않는다.
- SDK 입력과 재생 입력은 동일한 도메인 계약으로 전달한다.
- 데이터의 기준은 로컬 DB다. UI 이벤트 유실로 획득 보상이 사라지지 않게 한다.
- 세 명의 수정 경계를 경로 단위로 나누고, 공통 계약 변경은 구현과 문서를 같은 PR에서 갱신한다.
- 임계값을 시연 목적으로 낮추지 않는다. 필요한 과거 기록과 보상 상태를 시연 전용 데이터로 준비한다.
- SDK 좌표·지원 신호·지도 제공자·배포용 앱 ID는 실제 검증 전까지 확정된 사실로 취급하지 않는다. 담당자가 확인한 값은 [작업 계획의 검증 표](WORK_PLAN.md#6-외부-검증-항목)에 기록한다.

## 원문에서 주의할 점

기능명세서의 기능 표는 F-06만 선택이므로 필수 기능 ID는 **14개**다. 서두의 '필수 13개'라는 개수보다 기능별 우선순위 표를 따른다. F-13은 계산 필수·리플레이 선택으로 구분한다.

주행·정차 정의, 삭제 후 참조, 고스트 과거 기록 선택 등의 빈 부분은 [구현 결정](IMPLEMENTATION_RULES.md)에 명시했다. Pleos 정책과 SDK 지원 여부는 원문에서도 미결 사항이므로 이 문서가 검증을 대신하지 않는다.
